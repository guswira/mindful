## Rules Claude keeps breaking

- Add `const` to every widget constructor that can take it.
- Never use BuildContext after an `await` without `if (!context.mounted) return;`
- Never edit *.g.dart, *.freezed.dart — run build_runner instead.
- Never hardcode user-facing copy. Add it to lib/l10n/app_en.arb AND app_id.arb,
  use `context.l10n.x` (widgets) or `currentL10n.x` (no context). See SPEC.md Localization.
- Never edit lib/l10n/generated/ — it's regenerated by `flutter pub get` / `flutter gen-l10n`.
- When adding a package, use the Dart MCP server to check pub.dev for the current version.

## Definition of done

`flutter analyze --no-pub` is clean (zero warnings). `flutter test` passes.
New widgets need at least one widget test.

## Documentation

- Every public class, method, and function gets a dartdoc comment
- One line if the name already explains it. More only if behavior
  is non-obvious or has edge cases.
- No restating the name. `/// Gets the user` on `getUser()` is noise.
- Document the why, not the what.
- Params and return only if not obvious from types and names.
- Never write `// TODO` without a reason after it.

## Code style

- Prefer `const` everywhere it compiles. Every widget constructor, every list literal.
- Prefer `switch` expressions over if-else chains for exhaustive matches.
- No logic in build(). Extract to methods or controllers.
- No inline styles — colors and text styles from `Theme.of(context)` only.
- Smallest widget tree that works. No unnecessary wrapping widgets
  (e.g. no `Container` when `Padding` or `SizedBox` suffices).
- Prefer `ListView.builder` / `SliverList` over mapped lists in `Column`
  for anything that could scroll.
- Never `print()` — use `debugPrint()` or a logger.
- Null safety first: no `!` unless you can explain why it can't be null there.
